LC打包 2.0.0 · Windows 64 位

从 Releases 下载 LC-Packer-v2.0.0-full.zip 完整发行包，全部解压后双击根目录的 LC打包.exe。
Python 和 Qt 运行库已内置，无需另行安装 Python 或 PySide6。
单独程序 LC-Packer-v2.0.0.exe 内嵌全部 16 个模板，但不含外置工具包；离线安装工具请使用完整 ZIP。
完整 ZIP 包含 EXE、源码、16 个模板、四个工具安装包、JDK 对应源码归档与许可文件。
源码仓库及 GitHub 自动生成的源码 ZIP 不包含工具安装原包。

请放在可写目录，无需管理员权限。构建工作目录建议使用英文路径，输出 APK 可使用中文文件名。
配置 local-config.json、默认工作目录和输出目录保存在 EXE 同目录下。

完整 ZIP 随附的通用工具：
- Eclipse Temurin JDK 17.0.20.1+1，含 java / keytool，安装到 tools/jdk17。
- Apktool 3.0.3，安装到 tools/apktool。
- Android Build-Tools 36.1.0 的 aapt / zipalign / apksigner.jar，安装到 tools/android-build-tools。
- Android Platform-Tools 37.0.1 的 ADB 与配套 DLL，安装到 tools/platform-tools。
四个安装包在 tool-packages 目录；JDK 对应源码归档也在该目录，无需安装或解压。
源码文件名为 OpenJDK17U-jdk-sources_17.0.20.1_1.tar.gz。
工具来源、完整许可位置及模板说明见 THIRD_PARTY_NOTICES.md。

仍需自行准备：
- 自己的 MQB 工程及由同一工程生成的 LC。
- 手机助手；当前已验证的旧 0a14 LC 来自手机助手 3.7.2。
- 自己的签名密钥库、实际别名和密码；也可在界面中新建 .p12 密钥库。
手机助手、私有工程、用户脚本及签名密钥不随发行包提供。
ADB 用于设备检查，离线构建无需连接设备。

首次打包：
1. 打开“工具路径”页，点击“安装缺失工具 / 使用随包工具”。
   安装前会校验本地包大小与 SHA-256，可“刷新状态”或“取消安装”。
   取消时已成功安装的工具会保留。
   安装后自动绑定六个工具路径，保存普通配置并重新检测环境。
   也可手动选择已有工具；手机助手路径需自行选择。
   六个工具组及四项安装状态均显示用途、必需场景、版本与默认位置。
   刷新状态核对全部受管文件的大小与 SHA-256，缺失或损坏时可点击安装修复。
   修复会在 tools/.lc-backup-* 完整保留旧目录，确认无用后可自行清理。
2. 选择 MQB，从下拉列表选择 16 个内置模板之一并阅读说明，或选择匹配的外部模板。
   默认使用 510（支持雷电9）模板，其余 15 个模板均未设备实测。
   指定一个尚不存在的输出文件，填写应用信息。
3. 点击“开始捕获新 LC”，再到手机助手 3.7.2 中手动调试同一工程。
   也可选择已有 LC，但须自行确认与 MQB 对应；切换 MQB 会清空旧 LC 选择。
4. 选择自己的签名密钥，输入实际别名和密码。新配置的默认别名为 lcpacker。
   新建密钥时，仓库密码至少为 6 位。
5. 点击“环境检测”，修复所有构建必需项，再点击“构建签名 APK”。
6. 查看构建日志及输出 APK。已有 APK 不会被覆盖。

安装与状态刷新不修改系统环境变量或注册表，不启动 ADB；目录必须可写。
修改应用名称时，输出 APK 文件名会同步更新，并保留原输出目录。
“保存配置”和环境报告导出均不保存密码；修改配置后需重新检测。
请备份密钥、别名和密码，后续更新同一应用需要使用同一密钥。
APK 构建、签名验证与设备运行是不同阶段；构建成功不代表脚本已在设备上运行。

模板与当前兼容性：
16 个内置模板包括 501、510、560、标准版、精简版和企业版等，名称和逐项说明见界面与 README.md。
免 ROOT、自启、自运行、暂停、热更等标签来自原文件名，不表示功能已验证。
所有内置模板均为旧 0a14 格式，已清理样例 LC、ATC、UI、属性、信息、更新 URL 和注入示例任务。
原名标注热更的模板已清除示例更新地址，需自行配置验证。
原始包名、provider 和图标来自第三方模板；构建时按配置替换应用信息及相关身份字段。
DEX / native 运行时、授权逻辑和第三方授权组件配置保持原样，包括已有 RSA 配置常量。
嵌套的 assets/inject/test.apk 作为必要运行组件保留；模板不包含用户签名私钥文件。
模板作为构建资源提供，不作为独立应用运行。
仅原 510（支持雷电9）模板与手机助手 3.7.2 的旧 0a14 LC、雷电 9 / Android 9 Root 模拟器组合曾经设备验证。
界面中默认 root-510 的“已验证”仅指上述原组合；清理后的默认模板本次仅完成构建验证。
其余 15 个模板均未进行设备运行验证，请先验证所选模板与设备的实际功能。
手机助手 4.6 的 eflc LC 与上述旧模板不兼容，不能混用。
独立源码自动编译入口尚未验证，仍需手机助手手动调试并捕获 LC。
Root 真机、自定义 UI、附件执行和插件运行尚未完成设备验证。
非空 UIP / ATC 默认阻止打包；明确允许原样嵌入后仍会保留未验证警告。
其他模板、架构和设备的兼容性请结合 README.md 验证。

命令行示例（窗口版 EXE 需用 --log-file 保存输出；日志、报告文件必须尚不存在）：
.\LC打包.exe --log-file tools-status.log tools-status
.\LC打包.exe --log-file install-tools.log install-tools --config local-config.json
.\LC打包.exe --log-file doctor.log doctor --config local-config.json --report doctor.json
.\LC打包.exe --self-test self-test.json

install-tools / tools-status 可加 --root 指定程序根目录，默认使用程序目录。
安装从该目录的 tool-packages 读取工具包，安装到其 tools 下。
CLI 安装只有显式传入 --config 才保存路径；安装后可单独运行 doctor。
命令行签名密码通过 LC_PACKER_STORE_PASSWORD 提供，独立私钥密码通过 LC_PACKER_KEY_PASSWORD 提供。
不要把密码写入命令参数或配置文件；已有密钥应填写其实际别名。
--self-test 只加载自身界面，不进行设备运行验证。

源码入口为 lc_packer；开发、测试和重新构建命令见 README.md。
准备完整发行包时先从官方来源取回锁定工具包：
py -3 packaging/fetch_tool_packages.py
.\build_exe.ps1 -OutputDirectory dist\2.0.0
py -3 -m lc_packer.release --exe dist/2.0.0/LC打包.exe
工具取回脚本需要联网；本地发布命令默认生成 LC打包-v2.0.0.zip。
GitHub Release 使用 LC-Packer-v2.0.0-full.zip 和 LC-Packer-v2.0.0.exe 文件名。
最终用户使用完整 ZIP 安装工具无需联网。
Qt Designer 编辑通过源码中的 edit_ui.cmd 使用。
